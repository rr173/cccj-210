# histoware — 延迟直方图检查点入仓、班次汇总与班次回归归因工具

配送平台只保留各采集器定时上报的**累积延迟直方图检查点**，不收集原始请求。
本工具做三件事：

1. `load`：把 JSONL 累积检查点**按批**装入本地 SQLite 仓库，整批成功后分配递增、可查询的入仓版本；
2. `summary`：给定入仓版本 + 值班表 + 若干命名班次，产出一份可直接消费的 SQLite 结果库，
   区分**精确计数**、**只能给出上下界的计数**、以及**因覆盖不全不能给出总体计数**三种情况，并保留全部来源证据；
3. `attribute`：读取**两份已经生成的结果库**和一份显式配对清单，产出可查询、可追溯的 SQLite
   对比库，回答“本周某 SLO 切点的延迟恶化由哪些采集器贡献”。它**只读取结果库**，
   绝不重新读取原始检查点，也绝不重算任一侧的班次汇总。

只依赖 Python 标准库（Python ≥ 3.8），无需安装第三方包。

## 输入格式

### 检查点 JSONL（每行一个对象）

```json
{"region":"cn-1","collector":"a","generation":"g1","ts":1700000000,"revision":0,"cuts_ms":[10,20],"counts":[2,5],"total":7}
```

* 以 `(region, collector, generation, ts)` 标识一个检查点，`revision` 为非负整数修订号；
* `ts` 为 UTC 整秒；`cuts_ms` 为严格递增的正整数毫秒切点；`counts` 与切点等长、非负、随切点单调不减；
* 切点 `c` 的计数 = 自该世代开始、**严格早于** `ts` 且延迟**严格小于** `c` ms 的请求数；
  隐含 0ms 切点计数为 0，隐含 +∞ 切点计数为 `total`；
* 计数与总数允许达到 2^64−1：仓库与结果库一律以十进制 TEXT 存储计数/总数，
  汇总用 Python 任意精度整数计算，不经过二进制浮点，也不受 SQLite 有符号 64 位整数限制；
* 字段必须恰好为上述 8 个，重复键、空行、浮点数、布尔值、非单调计数、`total` 小于最大桶计数等均为坏行。

### 值班表 JSONL（汇总时由管理员指定）

```json
{"region":"cn-1","collector":"a","generation":"g1","start":1700000000,"end":1700003600}
```

* 半开时段 `[start, end)`；同一 `(region, collector)` 的时段不得重叠（首尾相接允许），空档表示该采集器本来不值班；
* 入班、离班、同一时刻换班只来自此表，绝不从有没有数据反推。

### 班次请求 JSONL

```json
{"name":"morning","region":"cn-1","start":1700000000,"end":1700003600,"cuts_ms":[10,50]}
```

`name` 唯一；`cuts_ms` 为要查询的正整数毫秒切点（可为空数组，只查总数）。

## 命令

```sh
# 装载一批（批号幂等：同批号同文件重送返回原版本；同批号不同文件报错）
python3 -m histoware load --db wh.db --batch 2026-11-20T00 --file checkpoints.jsonl

# 查看批次与版本
python3 -m histoware batches --db wh.db

# 生成结果库（--version 省略时取当前版本）
python3 -m histoware summary --db wh.db --version 3 \
    --roster roster.jsonl --request shifts.jsonl --out result.db
```

可运行示例：`sh examples/run_example.sh`（手算数据：交集 A 起点总数 3、10ms 以下 2，
终点总数 7、只有 20ms 切点计数 4 → 新增 4 个请求、10ms 以下 ∈ [0,2]；
交集 B 恰有 1 个 10ms 以下请求 → 班次 10ms 以下 ∈ [1,3]，总数 5）。

## 班次回归归因（attribute）

### 配对清单 JSONL（每行一个配对）

```json
{"id":"week-over-week-10ms","baseline_shift":"base-week","candidate_shift":"cand-week","cut_ms":10}
```

* 字段恰好为 `id`、`baseline_shift`、`candidate_shift`、`cut_ms`；`id` 在清单内唯一，空行/重复 id/坏 JSON 整次运行失败；
* 两侧必须**实际包含同名班次、同一切点、同一区域**：按名称与切点显式配对，
  名称无关的猜测、按行顺序或相似名称配对一律禁止；
* 一个配对只比较一个切点；同一对班次要比较多个切点就写多行（不同 `id`）。

### 计算口径（全部整数运算，计数为十进制 TEXT）

对每一对班次，先按结果库 `intersection` / `intersection_cut` 明细在**区域 + 采集器**上对齐：

* 某采集器只有在两侧的**每个应覆盖交集都可用**（`ok`）且该切点都有上下界时才进入“可比较范围”；
* 采集器超阈值请求数 = 该采集器请求总数 − 该切点“**严格小于切点**”请求数。
  下界用 `总数 − below_hi`、上界用 `总数 − below_lo`，上下界保持结果库中的原有含义，
  绝不取中点、也不假设两侧误差相互抵消；
* 采集器贡献区间 = 候选区间 − 基线区间：`[cand.lo − base.hi, cand.hi − base.lo]`；
* 判定：变化下界 **> 0** 为 `confirmed`（已证实贡献）；上界 > 0 但下界不 > 0 为
  `possible`（可能贡献）；上界不 > 0 为 `unproven`（未证实）；
* 整体超阈值**比例的百分点变化**以精确分数（分子/分母各一列，分母为正）存储，
  不经过二进制浮点；分母为零时百分点列留 NULL 并给出 `zero_denominator` 原因；
* 可比较范围内各采集器区间之和**严格等于**该范围的整体变化区间（加法闭合）。
  当范围外还有采集器或不可用交集时，范围外部分以显式 `unallocated_lo/hi` 报告，
  绝不摊派给任何采集器；完全可比较时未分配部分恰为 `[0,0]`。

### 状态与保护

配对状态为 `comparable` / `partial` / `not_comparable`。出现零分母、任一侧覆盖不全
（`partial`/`no_duty`）、采集器集合不一致、缺切点、班次缺失或区域冲突时，绝不发布貌似确定的
整体归因：保留可定位的输入班次与全部交集证据（含两端检查点世代/修订/批号/行号），
在 `pair_issue` 中写明机器可读原因，并标注实际可比较范围（`comparable_collectors`）。

### 命令

```sh
python3 -m histoware attribute \
    --baseline examples/attr_base_result.db \
    --candidate examples/attr_cand_result.db \
    --pairs examples/attr_pairs.jsonl \
    --out examples/attr_compare.db
```

可运行示例：`sh examples/run_attr_example.sh`（手算：基线总 25、超阈值 [12,17]；
候选总 30、超阈值 [17,19]；采集器 a 精确 +3（confirmed）、b ∈ [-1,4]（possible）、
c ∈ [-2,0]（unproven）；整体变化 [0,7]，未分配 [0,0]；另含一个缺切点的 not_comparable 配对）。

### 对比库结构

* `meta`：schema 版本、三个输入文件 SHA-256、运行统计 `stats_json`；
* `input_file`：基线/候选/清单三个输入的路径、摘要、字节数、来源结果库 meta 摘要；
* `pair_request`：逐行配对请求（含原始 JSON 文本与行号）；
* `pair`：每对的状态、两侧班次/区域/状态、整体与**可比较范围**内的总数与超阈值上下界、
  变化区间、未分配区间、整体与范围内百分点分数边界、采集器计数；
* `pair_issue`：每对的机器可读判定原因（如 `baseline_cut_missing`、`collector_only_candidate`、
  `collector_not_comparable`、`zero_denominator`、`empty_comparable_scope` 等）；
* `pair_collector`：逐采集器是否在范围内、两侧 due/ok 交集数、两侧超阈值区间、变化区间与贡献判定，
  支持按配对班次和采集器查询；
* `pair_intersection`：两侧**每个来源交集**一行，带源交集 id、状态、冲突原因与完整检查点血缘，
  以及该切点在源库中的上下界，任何数字都可回溯到来源结果库。

### 一致性与原子性

* 两个输入结果库都以 SQLite **只读模式**打开，归因不会改动任何输入；
* 对比库先写临时文件、完整提交后原子改名覆盖目标，输入无效、配对冲突或写出失败都不会用部分结果覆盖已有库；
* 相同请求重跑逻辑结果一致（仅 `created_utc` 等运行时字段不同）；
* 交换基线与候选：所有变化区间符号反转、贡献判定相应调整，而可比较性状态不变。

## 语义要点

* **版本与幂等**：每整批成功分配一个递增版本；同一检查点同修订、语义相同的重传不产生第二个修订、
  不改变最初批号/行号；内容不同则拒绝整批。更高修订可改变桶布局；迟到的低修订被保留但不会取代高修订。
  坏行、批内/与既存资料冲突、读入中断都不会推进可见版本，历史版本仍可重算。
* **交集**：班次与值班时段求交，正长度交集取**精确起止整秒**的检查点（同一值班世代、
  指定版本可见的最大修订）。缺端点不补零、不用邻近时刻代替；中间漏报不影响两端齐全的交集；
  跨班次的大交集计数从不按时长摊回小班次。换班时旧世代终点与新世代起点是两条不同记录。
* **冲突**：总数倒退、共同切点（含隐含端点）差值不单调、或某查询切点区间裁剪后为空，
  该交集整体记为 `conflict` 不可用，并记录发生冲突时所用的修订与切点，不回退旧修订。
* **区间估计**：两端都有该切点则精确作差；否则各端用相邻已知切点（含隐含 0/+∞）夹住累积计数，
  以「终点下界−起点上界、终点上界−起点下界」得区间，再与 `[0, 交集请求总数]` 相交。
  禁止插值、细分原桶或把有限上界写成精确值。
* **班次状态**：`complete`（全部应覆盖交集可用，给出总数与区间，上下界相等即 `exact=1`）、
  `partial`（有缺报/冲突：只发布带标记的已覆盖小计 `covered_*`，整体指标留空 NULL）、
  `no_duty`（零值班交集的专门状态，与完整零流量 `complete` 且总数 0 严格区分）。

## 结果库结构

* `meta`：入仓版本、值班表/请求内容摘要（SHA-256）、运行统计 `stats_json` 等；
* `shift` / `shift_cut`：按班次的总计与每切点上下界（计数为十进制 TEXT）；
* `intersection`：每个应覆盖交集的状态、两端检查点的世代/修订/批号/行号、两端总数与差值、冲突原因与切点；
  缺端点时保留另一端并注明缺哪端；
* `intersection_cut`：每个查询切点用于判断上下界的**原始相邻切点与计数**
  （切点 0 = 隐含零切点，NULL 切点 = 隐含 +∞，其计数为该端总数）。

## 索引、内存边界与一致性

* 端点查找走检查点主键索引 `(region, collector, generation, ts, revision)` 的 O(log n) 探测，
  并为每个班次/全部班次**从不重扫**检查点历史；相邻班次共享的端点由有界 LRU 缓存（默认 65536 条）复用；
* 装载与值班表使用文件后备临时表（`PRAGMA temp_store=1`）分块写入，整个文件从不一次装入内存；
  班次逐个处理、结果行定长分块写出，单班次工作内存只与该班次覆盖的值班时段数有关；
* 汇总期间全部仓库读取处于同一 WAL 快照事务并叠加 `version <= V` 过滤：
  即使此时有新批次提交，结果中也读不到比所选版本更新的端点；
* 结果库先写入临时文件、提交成功后原子改名覆盖目标，失败不会把已有结果换成部分完成的数据库；
  历史重算保证表内逻辑结果一致（不要求 SQLite 文件逐字节相同）；
* 每次汇总在 stdout 与结果库 `meta.stats_json` 中报告实际的端点查找次数、缓存复用次数与各表写出行数。

## 测试

```sh
python3 -m pytest tests/ -q
```

* `tests/test_load.py`：装载校验、幂等重送、批内冲突后同批重送、并发入仓、读入中断、2^64 边界；
* `tests/test_summary.py`：手算核对、班中换代与旧代终点缺失、共同切点差值下降、修订改布局后重出两个历史版本、
  缺端点/零值班/零流量、不摊回、版本隔离、64 位求和、目标库写出失败保护；
* `tests/test_randomized.py`：随机打乱记录与 JSON 键序，与独立参考实现 `tests/reference.py` 差分比对结果与切点证据；
* `tests/test_perf.py`：可重复生成的长历史 × 多采集器 × 多重叠班次，核对端点查找量不随历史总长增长
  （短/长历史各 17280 / 86400 个检查点，端点 SQL 查询数完全相同）。
* `tests/test_attribution.py`：归因手算核对——精确变化与加法闭合、相交但无法证实贡献（possible）、
  一升一降总体抵消、两侧覆盖不全、切点缺失、集合不一致、零分母、`no_duty`、反向比较符号反转、
  清单冲突/坏输入、目标写出失败保护、只读输入与 2^64 精度；
* `tests/test_attribution_random.py`：随机区间输入对照独立参考实现，核对比例分数边界、
  贡献判定边界、归因闭合与反向对称性；
* `tests/test_attribution_perf.py`：运行时生成多采集器/多配对数据，核对工作量只随被引用
  的配对规模增长、无关班次不增加工作量、证据行与写出计数一致。

大资料与数据库仅在运行时生成（pytest 临时目录），不提交 Git。
